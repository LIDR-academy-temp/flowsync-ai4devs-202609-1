# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

FlowSync is a course exercise repo (LIDR AI4Devs): an end-to-end TypeScript app with an AdonisJS 7 API in `backend/` and a React 19 + Vite SPA in `frontend/`. The two are independent npm projects with no root workspace, so run commands from inside each directory.

- **The backend already exists and is treated as read-only for this exercise.** Frontend work consumes it. Read the backend (especially validators) to learn the real API contract instead of guessing.
- `README.md` is generated from the course lesson ("no se edita a mano"). Don't edit it.
- `prompts.md` (root) and `docs/harness/comparacion.md` are exercise deliverables written by the student.
- Requires **Node.js 24+**. Older versions fail with `Unknown file extension ".ts"`.

## Commands

### Backend (`backend/`, serves http://localhost:3333)

```bash
npm install
cp .env.example .env && node ace generate:key   # first time only
node ace migration:run                           # SQLite DB at backend/tmp/db.sqlite3
npm run dev          # node ace serve --hmr
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
npm run format       # prettier (@adonisjs/prettier-config)
npm test             # node ace test (Japa)
node ace test functional                              # one suite (unit | functional)
node ace test --files tests/functional/auth.spec.ts   # one file
node ace test --tests "logs in with valid credentials" # one test by title
```

Test suites are defined in `adonisrc.ts`: `tests/unit/**/*.spec.ts` and `tests/functional/**/*.spec.ts`. Only `tests/bootstrap.ts` exists so far. `.env.test` sets `SESSION_DRIVER=memory`.

### Frontend (`frontend/`, serves http://localhost:5173)

```bash
npm install
npm run dev
npm run build    # tsc -b && vite build (this is also the typecheck)
npm run lint     # oxlint
```

The frontend is still the bare Vite template (`src/App.tsx`). It has no router, UI library (shadcn/ui is intended but not set up), formatter, or test runner yet.

## Backend architecture

Request flow: `start/routes.ts` → controller (`app/controllers`) → `request.validateUsing(<VineJS validator>)` → Lucid model → `ctx.serialize(Transformer.transform(model))`.

- **Response envelope**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps every payload in `{ data: ... }`. Clients must read `response.data`.
- **Auth**: the default guard is `api`, which uses opaque access tokens (prefix `oat_`) stored in `auth_access_tokens`. Clients send `Authorization: Bearer <token>`. Routes are protected with `middleware.auth()` (named middleware in `start/kernel.ts`). A session guard `web` is configured but unused by routes.
- **Routes** (all under `/api/v1`):
  - `POST auth/signup` → `NewAccountController.store`. Body is `{ fullName (nullable), email, password, passwordConfirmation }`, with password 8–32 chars and email unique. Returns `{ data: { user, token } }`.
  - `POST auth/login` → `AccessTokensController.store`. Body is `{ email, password }`. Returns `{ data: { user, token } }`.
  - `GET account/profile` (auth) → user. `POST account/logout` (auth) revokes the current token.
- **Errors**: `force_json_response_middleware` forces JSON for all responses. VineJS validation failures return 422 with an `errors` array of `{ field, rule, message }`. Bad login credentials come from `User.verifyCredentials`.
- **Transformers** (`app/transformers`) whitelist what's exposed. `UserTransformer` returns `id, fullName, email, createdAt, updatedAt, initials` and never the password hash.
- **CORS** allows any origin in dev (`config/cors.ts`) and an empty allowlist in production.
- **Imports** use Node subpath aliases from `package.json` (`#models/*`, `#validators/*`, `#controllers/*`, `#start/*`, etc.) with `.js`-mapped paths.

### Generated code: don't hand-edit

- `database/schema.ts` is regenerated by `node ace migration:run` from the DB. Models extend these generated classes (e.g. `User extends compose(UserSchema, withAuthFinder(hash))`), so schema changes go through a **new migration** and then a re-run. Never edit the table or `schema.ts` directly.
- `.adonisjs/` is regenerated by the `adonisrc.ts` init hooks (`indexEntities`, Tuyau `generateRegistry`) when the dev server or build starts. Routes reference controllers through `controllers.X` from `#generated/controllers`, so a new controller only becomes available after regeneration. `.adonisjs/client/registry` is a typed route registry exported by the backend package (`backend/registry`, `backend/data`) for typed API clients.


## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
